There is a difference between getting an answer faster and understanding a problem better.

AI can help with both. But a fluent answer can make it tempting to skip the second.

## Give it something to push against

A vague request invites a plausible response. A clear problem, a few constraints, and a concrete example create a more useful exchange.

Try asking for alternatives to an approach you already understand. Ask what assumptions could fail. Ask for a small counterexample that would break the logic.

The goal is to make your reasoning more visible, not to replace it with something that sounds convincing.

## Keep the responsibility

If you use generated SQL, inspect the joins. If you use a summary, check it against the source. If you use an explanation, see whether you can explain it to someone else without reading it back.

These checks are part of the work. They do not disappear because the first draft arrived quickly.

## Measure what improves

Time saved is useful, but it’s only one measure. Did the work become clearer? Did you notice an edge case earlier? Can another person maintain the result?

A good collaborator helps you see more. That is a better ambition than simply producing more.
